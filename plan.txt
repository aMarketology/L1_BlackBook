# BlackBook L1 — $BB Blockchain Plan
# The "Rules of the Game" for a High-Performance Agent Economy
#
# The job of the BlackBook L1 blockchain is to serve as the trustless settlement
# layer for AI agent transactions. It provides the "rules of the game" and the
# "field" where $BB tokens move — not just between human wallets, but between
# autonomous agents that sign and submit transactions without any human in the loop.
#
# $BB is the native token. 1 $BB = 10 cents. The peg is maintained by the market
# maker and escrow system built on top of the chain. The chain's only job is to
# make sure $BB moves correctly, immutably, and fast.

================================================================================
THE FOUR CORE JOBS
================================================================================

1. THE TRUTH MACHINE (Ordering & Immutability)
----------------------------------------------
The most important job: ensure every node agrees on who holds how many $BB
and in what order transactions were executed.

  - Preventing Double-Spend: If Agent-A has 1 $BB and submits two transfers
    simultaneously, the chain picks one as "first" and rejects the other.
  - Immutability: Once confirmed, a transaction can never be deleted or reversed.
  - PoH (Proof of History): A cryptographic clock (SHA-256 VDF chain) that
    timestamps every transaction. Validators don't waste time arguing about when
    something happened — the hash chain is the proof.

  STATUS: LIVE — poh_blockchain.rs + runtime/poh_service.rs are running.


2. THE GATEKEEPER (Security & Validation)
-----------------------------------------
Every $BB transfer must be authorized by its rightful owner via cryptographic proof.

  - Ed25519 Signature Verification: Every write (transfer, escrow, faucet) requires
    a valid signature over a canonical message string. L1 never holds private keys.
  - Parallel Sig Verification (Rayon): Batch verification across all CPU cores.
    On 16 cores, 100K sigs verify in ~375ms (fits inside a 400ms slot).
  - Consensus (Tower BFT): Validators vote on block finality using a lockout-based
    system mirroring Solana's Tower BFT.

  STATUS: LIVE — sigverify.rs + runtime/consensus.rs operational.
          Integration tests in tests/sealevel_sigverify.rs.


3. THE WORLD COMPUTER (Parallel Execution)
------------------------------------------
BlackBook L1 is not just a ledger — it is a parallel execution engine.

  - Sealevel: Transactions declare their account dependencies ahead of execution.
    Non-overlapping transactions execute concurrently across CPU threads.
  - Gulf Stream: Transactions are forwarded to the expected leader before the
    previous block is even finalised — filling the execution pipeline continuously.
  - SVM (Solana Virtual Machine): Executes both native $BB system transfers and
    SPL token operations (USDC bridge). Phase 2 adds arbitrary BPF programs.
  - Sharded Account State: 256 independent DashMap shards route accounts by their
    first pubkey byte, guaranteeing zero lock contention for unrelated accounts.

  AGENT USE CASE:
    Autonomous AI agents (trading bots, market makers, settlement agents) submit
    pre-signed $BB transactions directly to /sealevel/submit or /transfer/simple.
    Each agent holds its own Ed25519 keypair — generated locally or via FROST MPC.
    L1 verifies the signature and executes. No human approval. No session. No SSS.
    The agent IS the wallet.

  STATUS: LIVE — runtime/core.rs, svm/runtime.rs, svm/sharded_state.rs.


4. THE ECONOMIC ENFORCER (Escrow & Settlement)
----------------------------------------------
The chain manages the on-chain mechanics of the $BB economy.

  - Escrow PDA: Agents and users lock $BB into a global escrow account
    via POST /escrow/deposit.
  - L2 Markets: Off-chain orderbooks run their logic, then the market submits
    a Merkle state root via POST /escrow/submit-state-root.
  - Withdrawals: Winners exit with a Merkle proof via POST /escrow/withdraw.
    L1 verifies the proof before releasing funds.
  - Admin Mint/Burn: The Dealer address can mint/burn $BB to maintain the peg.
  - USDC Bridge: SPL-compatible USDC minting/transfer for the stablecoin reserve
    that backs $BB at 10:1.
  - Fees: Currently zero (dev phase). Will be added before mainnet.

  STATUS: LIVE — escrow handlers, admin mint/burn, USDC SPL engine.

================================================================================
WHAT WE DON'T HAVE YET (Missing for Production)
================================================================================

  1. VALIDATOR NETWORK
     Currently single-node (one writer, optional readers).
     Real PoS slashing and multi-validator consensus are not yet enforced.
     LeaderSchedule exists but stake-weighted selection is simulated.

  2. FEE MARKET
     All transactions are free. No gas fee collection or priority queue
     based on fee bids. Required before mainnet to prevent spam.

  3. ARBITRARY PROGRAMS (BPF / rBPF)
     SVM Phase 1 handles native transfers and SPL tokens only.
     Phase 2 adds loadable BPF programs (full smart contract support).

  4. LIGHT CLIENT / MERKLE SYNC
     Full light-client sync protocol is not implemented. Merkle proofs
     are used only in the escrow withdraw path today.

  5. STAKING + SLASHING
     No on-chain bond or slash mechanism. Validators cannot yet be
     economically penalized for equivocation.

  6. AGENT SDK
     A typed Rust/JS SDK that agents use to construct and sign $BB
     transactions — wrapping the sigverify canonical message formats,
     nonce management, and retry logic.
